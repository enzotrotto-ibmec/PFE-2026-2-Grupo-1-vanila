# Sprint 1: Kick-off e criação do repositório

**Período:** 12/10/2026 a 18/10/2026
**Scrum Master:** Enzo Trotto

## Sprint Goal

> Criar o repositório do site Vanilla e os arquivos iniciais, para que a equipe possa começar a desenvolver.

## Sprint Backlog

| Item | Tarefa | Responsável | Status |
|---|---|---|---|
| PB-01 | Criar o repositório no GitHub com o README inicial (14/10) | Enzo Trotto | Concluído |
| PB-01 | Adicionar os arquivos iniciais (`index.html`, `script.js` e `style.css`) (14/10) | Enzo Trotto | Concluído |

## Sprint Review

- **Entregue:** repositório criado e arquivos iniciais (14/10).
- **Não entregue:** nada além da criação do repositório. No histórico do Git não há registro de desenvolvimento do site nesta sprint.
- **Principal aprendizado:** os arquivos iniciais (`script.js` e `style.css` vazios, `index.html` básico) acabaram sendo apagados na sprint seguinte, quando a equipe definiu a estrutura real do projeto (`pages/`, `css/`, `js/` e `assets/`). A estrutura devia ter sido combinada antes de criar os arquivos.

## Sprint Retrospective

| O que funcionou | O que não funcionou | Ação para a próxima sprint |
|---|---|---|
| Repositório criado cedo, deixando o projeto pronto para receber o código. | A equipe não dividiu as tarefas nem definiu a estrutura de pastas logo no início. | Fazer a Sprint Planning no começo da semana, definindo a estrutura de pastas e quem fica com cada arquivo. |
| | Nenhum entregável do site ficou pronto, e o trabalho foi todo para a sprint seguinte. | Dividir o trabalho em entregas ao longo da semana, e não só nos últimos dias. |
